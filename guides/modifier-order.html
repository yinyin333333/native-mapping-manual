Compose recipe options in a deliberate order

Reuse a combat pool and a reward extension. Applying them in a different order changes which traits the player can receive.

1. Prepare data2. Configure3. Use the map4. Adapt it

What to create or confirm

File / systemRequired work
CubeMainExact Red Portal recipes: tsc + r01 and tsc + r02.
ItemStatCostPlayer attack speed 93, movement 96 and Magic Find 80.
LevelsOne eligible group [2].

See how to find data IDs, CubeMain row syntax and HUD node installation.

Use the item, Level, stat and skill IDs from your effective mod data. The complete TOML below does not create TXT rows. If you change an input combination, update both CubeMain and its route.

The decisions in this configuration

  1. Define the reusable operations

    combat replaces the pool with attack and movement. reward extends the current pool with find.

  2. Apply combat, then reward

    The mixed recipe ends with [attack, movement, find]. Two distinct traits are drawn from three equally weighted candidates.

  3. Reverse the order for a combat-only recipe

    The second route applies reward, then combat. The final replace removes find from the candidate pool, leaving exactly attack and movement.

# The same modifiers in different orders produce different candidate pools.
# Exact Red Portal recipes: tsc+r01; tsc+r02.
config_version = 1

[traits.attack]
text = "Player Attack Speed {signed}%"
stats = [{ stat_id = 93, target = "player", value = 20 }]
[traits.movement]
text = "Player Movement {signed}%"
stats = [{ stat_id = 96, target = "player", value = 15 }]
[traits.find]
text = "Player Magic Find {signed}%"
stats = [{ stat_id = 80, target = "player", value = 75 }]

[modifiers.combat]
trait_pool_mode = "replace"
trait_pool = ["attack", "movement"]
[modifiers.reward]
trait_pool_mode = "extend"
trait_pool = ["find"]

[cube_routes.mixed]
inputs = ["tsc", "r01"]
tier = "expedition"
modifiers = ["combat", "reward"]
[cube_routes.combat]
inputs = ["tsc", "r02"]
tier = "expedition"
modifiers = ["reward", "combat"]

[tiers.expedition]
trait_count = { min = 2, max = 2 }

[tiers.expedition.groups.field]
levels = [2]
entrances = [{ level = 2, weight = 1 }]
density = 150
trait_pool = []

Close the game, back up <scope>/d2rloader/config/native-mapping.toml, then replace it with this file and restart the game and loader. Do not append a complete file to another complete file.

What the player should experience

Action / resultExpected behavior
tsc + r01 · combat → rewardTwo of three candidates. MF may or may not be included.
tsc + r02 · reward → combatAttack and movement are both selected.
Both recipesSame tier, destination and density. The modifier order changes the effect policy.

Use the recipe in a fresh game with the required ingredients, enter its portal, and open the automap. Check the tier, density and effect text against the result above. Syntax and rolls are checked against the configuration core; these steps are the in-game checks to perform in your own mod.

Design boundary. Conflicting trait_count overrides are errors, not “last modifier wins.” Pool replacement is ordered; count conflict handling is a separate rule.

Change the behavior intentionally

Guarantee MF in the mixed recipe
Force find and set the total count deliberately; extending a pool only makes it eligible.
Share one count override
Place a count override in one modifier, or keep all participating overrides identical.
Add another extension
Append its modifier after the last replace if its candidates should remain available.

When merging this design into your existing TOML, copy its referenced traits and modifiers as well as the route and tier. Keep only one root configuration and HUD table, rename colliding identifiers consistently, and check Level overlap across every tier.
