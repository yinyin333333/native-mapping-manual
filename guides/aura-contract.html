EXACT QUANTITIES & FORCED TRAITS

Add a paid aura while keeping two random traits

A plain recipe rolls two traits. A second recipe consumes two matching runes and adds Conviction without taking away either random slot.

1. Prepare data2. Configure3. Use the map4. Adapt it

Complete standalone TOML · example values, not a balance preset · no plugin rebuild required

01 / PREPARE THE GAME DATA

What to create or confirm

File / systemRequired work
CubeMainTwo exact Red Portal recipes: tsc and tsc + r01 + r01. The second requires two copies, not one.
Skills / statsMonster Conviction skill 123; player MF 80, XP 85 and monster movement 67.
LevelsOne group [2]; use a fresh game to compare both recipes on that same destination.

Use the item, Level, stat and skill IDs from your effective mod data. The complete TOML below does not create TXT rows. If you change an input combination, update both CubeMain and its route.

02 / CONFIGURE THE MAP

The decisions in this configuration

  1. Keep the aura out of the ordinary pool

    The group pool contains find, experience and haste. A plain recipe can never randomly select Conviction.

  2. Force the aura in a dedicated modifier

    forced_traits = ["conviction"] attaches the aura to the paid route only. The aura level rolls 5 or 10.

  3. Increase the total count

    The normal count is 2. The paid modifier changes it to 3: one forced aura plus two distinct random traits from the original pool.

# The paid recipe adds one aura without replacing the two random traits.
# Required exact Red Portal recipes: tsc; tsc+r01+r01.
# Confirm Conviction skill 123 and the stat/Level IDs in effective data.
config_version = 1

[traits.conviction]
text = "Monster Conviction Lv.{value0}"
monster_aura = { skill_id = 123, level = { min = 5, max = 10, step = 5 } }
[traits.find]
text = "Magic Find {signed}%"
stats = [{ stat_id = 80, target = "player", value = { min = 25, max = 75, step = 25 } }]
[traits.experience]
text = "Experience {signed}%"
stats = [{ stat_id = 85, target = "player", value = 20 }]
[traits.haste]
text = "Monster Movement {signed}%"
stats = [{ stat_id = 67, target = "monster", value = 20 }]

[modifiers.aura_contract]
forced_traits = ["conviction"]
trait_count = { min = 3, max = 3 }

[cube_routes.plain]
inputs = ["tsc"]
tier = "contract"
[cube_routes.contracted]
inputs = ["tsc", "r01", "r01"]
tier = "contract"
modifiers = ["aura_contract"]

[tiers.contract]
trait_count = { min = 2, max = 2 }

[tiers.contract.groups.field]
levels = [2]
entrances = [{ level = 2, weight = 1 }]
density = 175
trait_pool = ["find", "experience", "haste"]

Close the game, back up <scope>/d2rloader/config/native-mapping.toml, then replace it with this file and restart the game and loader. Do not append a complete file to another complete file.

03 / USE THE MAP

What the player should experience

Action / resultExpected behavior
tscTwo of find, experience and haste; no aura.
tsc + r01 + r01Conviction plus two of the same three random traits.
tsc + r01Does not match either documented route. Extra ingredients are not automatically interpreted as modifiers.

Use the recipe in a fresh game with the required ingredients, enter its portal, and open the automap. Check the tier, density and effect text against the result above. Syntax and rolls are checked against the configuration core; these steps are the in-game checks to perform in your own mod.

Design boundary. A resolved map supports one monster aura. Keep competing aura traits out of the pool. A monster already using the same right-skill ID retains that existing skill in the current native branch.

04 / ADAPT THE DESIGN

Change the behavior intentionally

Charge a different exact item
Change both CubeMain and the route inputs. Changing only TOML does not create the recipe.
Make the aura deterministic
Replace its level range with a fixed integer.
Spend one existing slot on the aura
Remove the count override. With the tier count still 2, the result becomes one forced aura plus one random trait.

When merging this design into your existing TOML, copy its referenced traits and modifiers as well as the route and tier. Keep only one root configuration and HUD table, rename colliding identifiers consistently, and check Level overlap across every tier.
