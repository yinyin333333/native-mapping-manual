PLAYER EFFECTS

Let the recipe choose a player bonus package

Offer melee, caster and finder expeditions from one tier. The recipe makes the choice explicitly, and the resulting map carries that package.

1. Prepare data2. Configure3. Use the map4. Adapt it

Complete standalone TOML · example values, not a balance preset · no plugin rebuild required

01 / PREPARE THE GAME DATA

What to create or confirm

File / systemRequired work
CubeMainExact Red Portal recipes for tsc; tsc + r01; tsc + r02.
ItemStatCostPlayer attack speed 93, movement 96, cast speed 105, Magic Find 80 and experience 85.
LevelsTwo disjoint groups: [2] and [8, 9].

Use the item, Level, stat and skill IDs from your effective mod data. The complete TOML below does not create TXT rows. If you change an input combination, update both CubeMain and its route.

02 / CONFIGURE THE MAP

The decisions in this configuration

  1. Put each loadout in one trait

    A loadout may contain several player stats. Each package still occupies one trait slot.

  2. Force the selected package

    Every route references its own modifier. The modifier forces melee, caster or finder; the group’s random pool is empty.

  3. Share the destination rules

    All routes reference expedition. Both map groups use 150% density. The item recipe does not need a separate copy of the tier.

# Recipes choose the player bonus package; they do not detect character class.
# Required exact Red Portal recipes: tsc; tsc+r01; tsc+r02.
# Check Level and stat IDs in effective data.
config_version = 1

[traits.melee]
text = "Melee: attack speed {signed0}%, movement {signed1}%"
stats = [
  { stat_id = 93, target = "player", value = 20 },
  { stat_id = 96, target = "player", value = 15 }
]

[traits.caster]
text = "Caster: cast speed {signed0}%, movement {signed1}%"
stats = [
  { stat_id = 105, target = "player", value = 20 },
  { stat_id = 96, target = "player", value = 15 }
]

[traits.finder]
text = "Finder: Magic Find {signed0}%, experience {signed1}%"
stats = [
  { stat_id = 80, target = "player", value = 75 },
  { stat_id = 85, target = "player", value = 15 }
]

[modifiers.melee]
forced_traits = ["melee"]
[modifiers.caster]
forced_traits = ["caster"]
[modifiers.finder]
forced_traits = ["finder"]

[cube_routes.melee]
inputs = ["tsc"]
tier = "expedition"
modifiers = ["melee"]
[cube_routes.caster]
inputs = ["tsc", "r01"]
tier = "expedition"
modifiers = ["caster"]
[cube_routes.finder]
inputs = ["tsc", "r02"]
tier = "expedition"
modifiers = ["finder"]

[tiers.expedition]
trait_count = { min = 1, max = 1 }

[tiers.expedition.groups.field]
levels = [2]
entrances = [{ level = 2, weight = 1 }]
density = 150
trait_pool = []

[tiers.expedition.groups.cave]
levels = [8, 9]
entrances = [{ level = 8, weight = 1 }]
density = 150
trait_pool = []

Close the game, back up <scope>/d2rloader/config/native-mapping.toml, then replace it with this file and restart the game and loader. Do not append a complete file to another complete file.

03 / USE THE MAP

What the player should experience

Action / resultExpected behavior
tscPlayer attack speed +20%, movement +15%.
tsc + r01Player cast speed +20%, movement +15%.
tsc + r02Player MF +75%, XP +15%.
Another party member enters the mapThat player receives the same map’s player package; bonuses are not reserved for the recipe user.

Use the recipe in a fresh game with the required ingredients, enter its portal, and open the automap. Check the tier, density and effect text against the result above. Syntax and rolls are checked against the configuration core; these steps are the in-game checks to perform in your own mod.

Design boundary. “Melee” and “caster” are author-chosen labels. The plugin does not inspect character class or equipment to select them. The recipe and map result own the choice.

04 / ADAPT THE DESIGN

Change the behavior intentionally

Add a random complication
Set the total count to 2 and add a monster trait pool large enough for one extra selection.
Guarantee the destination too
Use a tier with a single eligible group. This example deliberately shares two destinations.
Create a fourth package
Define the trait, a forcing modifier and a distinct exact CubeMain/route input combination.

When merging this design into your existing TOML, copy its referenced traits and modifiers as well as the route and tier. Keep only one root configuration and HUD table, rename colliding identifiers consistently, and check Level overlap across every tier.
