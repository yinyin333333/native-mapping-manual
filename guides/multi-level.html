Build a map that spans several Levels

One entrance, five Levels, one map result. A recraft that touches this group replaces all five Levels after the area is clear.

1. Prepare data2. Configure3. Use the map4. Adapt it

What to create or confirm

File / systemRequired work
CubeMainAn exact tsc input recipe with a Red Portal output.
LevelsExisting connected Levels 21, 22, 23, 24 and 25. Replace these illustrative IDs with your intended area.

See how to find data IDs, CubeMain row syntax and HUD node installation.

Use the item, Level, stat and skill IDs from your effective mod data. The complete TOML below does not create TXT rows. If you change an input combination, update both CubeMain and its route.

The decisions in this configuration

  1. Choose the complete area

    Put all five IDs in levels. This list defines the effect area and the entire group that will be replaced if a later selection overlaps it; it is not a list of independent random destinations.

  2. Choose the portal landing

    Keep only Level 21 in entrances. The portal always lands there; the remaining floors are reached through their normal connections.

  3. Set the map rules once

    The group uses density = 150 and zero traits. Every listed Level belongs to that same resolved map; you do not repeat the group table for each floor.

# Complete example: one map spans five Levels; the portal enters Level 21.
# Requires an exact tsc -> Red Portal recipe and usable Levels 21-25.
config_version = 1

[cube_routes.scroll_map]
inputs = ["tsc"]
tier = "tier1"

[tiers.tier1]
trait_count = { min = 0, max = 0 }

[tiers.tier1.groups.five_levels]
weight = 100
levels = [21, 22, 23, 24, 25]
entrances = [{ level = 21, weight = 100 }]
density = 150
trait_pool = []

Close the game, back up <scope>/d2rloader/config/native-mapping.toml, then replace it with this file and restart the game and loader. Do not append a complete file to another complete file.

What the player should experience

Action / resultExpected behavior
Portal destinationLevel 21.
On floors 22–25The same map rules remain in effect.
A second recipe in the same gameThe same group is selected again. After everyone leaves all five Levels and rooms are ready, its old portals and hunting content are cleared and regenerated.

Use the recipe with the required ingredients, enter its portal, and open the automap. Before repeating a craft, recover needed items and player corpses and move all players and allies out of every Level in the replacement area; rooms must no longer be in use. See the repeat-craft procedure. Check the tier, density and effect text against the result above. Syntax and rolls are checked against the configuration core; these steps are the in-game checks to perform in your own mod.

Design boundary. Listing five Levels does not create corridors or generate five new instances. Confirm their actual connections in your mod before treating them as a traversable dungeon.

Change the behavior intentionally

Allow a second entrance
Add { level = 25, weight = 1 } to entrances. With equal weights, the portal chooses either end; the effect area is still all five Levels.
Make floors independent maps
Create disjoint groups, each containing the Levels that should share one result. Terrain links stay a game-data concern.
Add another full dungeon
Add another group using entirely different Levels. It can coexist with the first dungeon; a later craft still rolls both groups and may replace either one.

When merging this design into your existing TOML, copy its referenced traits and modifiers as well as the route and tier. Keep only one root configuration and HUD table, rename colliding identifiers consistently, and check Level overlap across every tier to understand which entire groups will be replaced.
