SHARED ROLLS & PENALTIES

Roll one resistance penalty across four stats

Trade reduced player resistances for a fixed Magic Find bonus. Keep all four resistance penalties equal while drawing a new value for each new map.

1. Prepare data2. Configure3. Use the map4. Adapt it

Complete standalone TOML · example values, not a balance preset · no plugin rebuild required

01 / PREPARE THE GAME DATA

What to create or confirm

File / systemRequired work
CubeMainAn exact tsc → Red Portal recipe.
ItemStatCostPlayer fire/lightning/cold/poison resistance IDs 39, 41, 43, 45; Magic Find 80.
LevelsA two-Level group [8, 9].

Use the item, Level, stat and skill IDs from your effective mod data. The complete TOML below does not create TXT rows. If you change an input combination, update both CubeMain and its route.

02 / CONFIGURE THE MAP

The decisions in this configuration

  1. Use group baselines for the penalty

    Group baselines allow ranges and apply without spending trait slots. Tier baselines are fixed-only.

  2. Give all four entries the same roll_group

    Every penalty entry uses roll_group = "penalty" and the identical range -30…-10 with step 10, inside the same array.

  3. Write one readable HUD line

    Only the first resistance entry needs text. It reports the shared value once; the other three stat entries still apply.

# One roll reduces all four player resistances by the same amount.
# Required CubeMain recipe: exact tsc -> Red Portal.
# Stat IDs refer to the effective ItemStatCost table.
config_version = 1

[cube_routes.trial]
inputs = ["tsc"]
tier = "trial"

[tiers.trial]
trait_count = { min = 0, max = 0 }
base_stats = [
  { stat_id = 80, target = "player", value = 100, text = "Trial Magic Find {signed}%" }
]

[tiers.trial.groups.underground]
levels = [8, 9]
entrances = [{ level = 8, weight = 1 }]
density = 150
base_stats = [
  { stat_id = 39, target = "player", value = { min = -30, max = -10, step = 10 }, roll_group = "penalty", text = "All Resistances {signed}%" },
  { stat_id = 41, target = "player", value = { min = -30, max = -10, step = 10 }, roll_group = "penalty" },
  { stat_id = 43, target = "player", value = { min = -30, max = -10, step = 10 }, roll_group = "penalty" },
  { stat_id = 45, target = "player", value = { min = -30, max = -10, step = 10 }, roll_group = "penalty" }
]

Close the game, back up <scope>/d2rloader/config/native-mapping.toml, then replace it with this file and restart the game and loader. Do not append a complete file to another complete file.

03 / USE THE MAP

What the player should experience

Action / resultExpected behavior
Possible resistance rollsAll four are -30, all four are -20, or all four are -10.
Every resultPlayer MF +100%, density 150%, zero selected traits.
Leave and re-enter the mapThe resolved penalty stays the same. It is not rolled again or repeatedly added.

Use the recipe in a fresh game with the required ingredients, enter its portal, and open the automap. Check the tier, density and effect text against the result above. Syntax and rolls are checked against the configuration core; these steps are the in-game checks to perform in your own mod.

Design boundary. Using the same roll_group name in different arrays does not synchronize them. All four entries must share one array and exactly matching range definitions.

04 / ADAPT THE DESIGN

Change the behavior intentionally

Give a defensive bonus instead
Use positive bounds such as 10…30. The mechanism is the same; balance and effective stat behavior remain your mod’s responsibility.
Make each resistance independent
Remove roll_group. Each entry then resolves its own range.
Turn the trial into an optional trait
Move the four entries into one trait’s stats array and place that trait in a pool or force it through a modifier.

When merging this design into your existing TOML, copy its referenced traits and modifiers as well as the route and tier. Keep only one root configuration and HUD table, rename colliding identifiers consistently, and check Level overlap across every tier.
