Keep a challenge and its reward together

Every roll should carry its own compensation: faster monsters with Magic Find, or physical resistance with experience. Bundle the pair into one trait.

1. Prepare data2. Configure3. Use the map4. Adapt it

What to create or confirm

File / systemRequired work
CubeMainOne exact tsc → Red Portal recipe.
ItemStatCostMonster movement 67, physical resistance 36, player Magic Find 80 and experience bonus 85.
LevelsLevel 2, or a suitable non-town destination from your mod.

See how to find data IDs, CubeMain row syntax and HUD node installation.

Use the item, Level, stat and skill IDs from your effective mod data. The complete TOML below does not create TXT rows. If you change an input combination, update both CubeMain and its route.

The decisions in this configuration

  1. Define complete packages

    hunters_bargain contains both monster movement +20 and player MF +75. armored_bargain contains physical resistance +10 and player XP +25.

  2. Select exactly one package

    The tier sets trait_count = { min = 1, max = 1 }. Group weights do not choose these effects; trait weights 70 and 30 choose between the packages.

  3. Add an unconditional reward separately

    The tier baseline grants player MF +25 on every result. With the hunters trait, it coalesces with the trait bonus to +100 MF.

# A challenge and its reward are selected together as ONE trait.
# Required CubeMain recipe: exact tsc -> Red Portal.
# Check Level and ItemStatCost IDs against effective mod data.
config_version = 1

[traits.hunters_bargain]
weight = 70
text = "Hunters: monster movement {signed0}%, player MF {signed1}%"
stats = [
  { stat_id = 67, target = "monster", value = 20 },
  { stat_id = 80, target = "player", value = 75 }
]

[traits.armored_bargain]
weight = 30
text = "Armored: monster physical resist {signed0}%, player XP {signed1}%"
stats = [
  { stat_id = 36, target = "monster", value = 10 },
  { stat_id = 85, target = "player", value = 25 }
]

[cube_routes.bargain]
inputs = ["tsc"]
tier = "bargain"

[tiers.bargain]
trait_count = { min = 1, max = 1 }
base_stats = [
  { stat_id = 80, target = "player", value = 25, text = "Map Magic Find {signed}%" }
]

[tiers.bargain.groups.field]
levels = [2]
entrances = [{ level = 2, weight = 1 }]
density = 175
trait_pool = ["hunters_bargain", "armored_bargain"]

Close the game, back up <scope>/d2rloader/config/native-mapping.toml, then replace it with this file and restart the game and loader. Do not append a complete file to another complete file.

What the player should experience

Action / resultExpected behavior
Hunters package · 70% trait weight175% density; monster movement +20%; player MF +100% total.
Armored package · 30% trait weight175% density; monster physical resistance +10; player MF +25% and XP +25%.
Leaving the mapTemporary player bonuses are cleared according to each player’s map membership.

Use the recipe with the required ingredients, enter its portal, and open the automap. Before repeating a craft, recover needed items and player corpses and move all players and allies out of every Level in the replacement area; rooms must no longer be in use. See the repeat-craft procedure. Check the tier, density and effect text against the result above. Syntax and rolls are checked against the configuration core; these steps are the in-game checks to perform in your own mod.

Design boundary. Separate “danger” and “reward” traits do not guarantee one of each. A pool draws traits without replacement; it does not understand categories. Put inseparable effects in one trait.

Change the behavior intentionally

Always give both packages
Set the count to 2. Both distinct traits are selected; their effects combine.
Make the choice rarer
Change the trait weight. Weight changes the chance of the whole package, not individual stats.
Roll a value inside the package
Replace a fixed value with an integer range. Separate values roll independently unless they share a valid roll_group.

When merging this design into your existing TOML, copy its referenced traits and modifiers as well as the route and tier. Keep only one root configuration and HUD table, rename colliding identifiers consistently, and check Level overlap across every tier to understand which entire groups will be replaced.
