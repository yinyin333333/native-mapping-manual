Build a three-tier progression loop

Combine entry items, disjoint destinations, escalating baselines, paired traits and next-tier drops. This is a complete TOML design with an explicit game-data contract.

1. Prepare data2. Configure3. Use the map4. Adapt it

What to create or confirm

File / systemRequired work
ItemsDefine custom item codes nm1, nm2 and nm3, including their ordinary item data and display strings. Supply the initial nm1 through your mod’s existing acquisition path.
CubeMainThree exact Red Portal recipes: nm1, nm2 and nm3.
TreasureClassExMapping_Tier1 rewards nm2; Mapping_Tier2 rewards nm3. Keep these roots out of ordinary monster TC trees.
Levels / statsSix disjoint groups shown below; resistance IDs 39/41/43/45, physical resistance 36, monster movement 67, MF 80 and XP 85.

See how to find data IDs, CubeMain row syntax and HUD node installation.

Use the item, Level, stat and skill IDs from your effective mod data. The complete TOML below does not create TXT rows. If you change an input combination, update both CubeMain and its route.

The decisions in this configuration

  1. Give each tier its own destinations

    tier1 owns [2] and [3]; tier2 owns [8,9] and [10]; tier3 owns [21,22,23] and [24,25]. No overlap consumes a later tier’s candidate.

  2. Build the fixed difficulty baseline

    Ranks 1–3 use monster elemental-resistance bonuses +0/+5/+10 and density 150/200/250%. Each map also selects one paired challenge/reward trait.

  3. Connect rewards to the next entry recipe

    tier1’s supplemental TC points to nm2, whose CubeMain recipe opens tier2. tier2 similarly supplies nm3. There is no progression table on tier3.

  4. Author the TC contents in TXT

    Use the selected fields below in real rows. TOML only names the root; it does not create those rows or dictate a guaranteed drop.

# Requires custom nm1/nm2/nm3 items and exact Red Portal CubeMain recipes.
# Define Mapping_Tier1 and Mapping_Tier2 in TreasureClassEx before enabling.
# Levels and stats below are illustrative; use effective mod data.
config_version = 1

[traits.hunters]
text = "Hunters: monster movement {signed0}%, Magic Find {signed1}%"
stats = [
  { stat_id = 67, target = "monster", value = 20 },
  { stat_id = 80, target = "player", value = 50 }
]
[traits.armored]
text = "Armored: monster physical resist {signed0}%, experience {signed1}%"
stats = [
  { stat_id = 36, target = "monster", value = 10 },
  { stat_id = 85, target = "player", value = 20 }
]

[cube_routes.tier1]
inputs = ["nm1"]
tier = "tier1"

[cube_routes.tier2]
inputs = ["nm2"]
tier = "tier2"

[cube_routes.tier3]
inputs = ["nm3"]
tier = "tier3"

[tiers.tier1]
difficulty_rank = 1
trait_count = { min = 1, max = 1 }
base_stats = [
  { stat_id = 39, target = "monster", value = 0, text = "Tier Monster All Resistances {signed}%" },
  { stat_id = 41, target = "monster", value = 0 },
  { stat_id = 43, target = "monster", value = 0 },
  { stat_id = 45, target = "monster", value = 0 },
]

[tiers.tier1.progression]
treasure_class = "Mapping_Tier1"
trigger = "all_monsters"

[tiers.tier1.groups.route1]
levels = [2]
entrances = [{ level = 2, weight = 1 }]
density = 150
trait_pool = ["hunters", "armored"]

[tiers.tier1.groups.route2]
levels = [3]
entrances = [{ level = 3, weight = 1 }]
density = 150
trait_pool = ["hunters", "armored"]

[tiers.tier2]
difficulty_rank = 2
trait_count = { min = 1, max = 1 }
base_stats = [
  { stat_id = 39, target = "monster", value = 5, text = "Tier Monster All Resistances {signed}%" },
  { stat_id = 41, target = "monster", value = 5 },
  { stat_id = 43, target = "monster", value = 5 },
  { stat_id = 45, target = "monster", value = 5 },
]

[tiers.tier2.progression]
treasure_class = "Mapping_Tier2"
trigger = "all_monsters"

[tiers.tier2.groups.route1]
levels = [8, 9]

density = 200

[tiers.tier2.groups.route2]
levels = [10]

density = 200

[tiers.tier3]

What the player should experience

Action / resultExpected behavior
Open with nm1One tier1 group becomes active; its qualifying monster drops receive the Mapping_Tier1 supplemental call.
Find nm2 and use its recipeA tier2 group can open in the same game because its Levels are disjoint from tier1.
Finish tier3Normal and trait-based gameplay continue. No automatic completion reward or next-tier call is configured.
Consume all candidatesEach tier has two possible activations per game if both eligible groups are used. Re-entering an existing map does not create another run.

Use the recipe in a fresh game with the required ingredients, enter its portal, and open the automap. Check the tier, density and effect text against the result above. Syntax and rolls are checked against the configuration core; these steps are the in-game checks to perform in your own mod.

Design boundary. A next-tier item is a chance-based TC reward here, not a map-clear reward. Opening a map, killing every monster or raising Picks does not itself guarantee progression.

Change the behavior intentionally

Add tier3 crafting rewards
Define a dedicated reward TC and add tier3 progression. It may contain several child TCs; it need not drop another entry item.
Use a shared destination pool
Follow the shared-pool task instead, accepting cross-tier exclusion in the same game.
Add a premium tier2 recipe
Point a distinct exact recipe to tier2 and attach a modifier. Keep the original tier2 route for the ordinary item.

When merging this design into your existing TOML, copy its referenced traits and modifiers as well as the route and tier. Keep only one root configuration and HUD table, rename colliding identifiers consistently, and check Level overlap across every tier.
