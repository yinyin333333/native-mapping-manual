Build a three-tier progression loop

Combine entry items, disjoint destinations, escalating baselines, paired traits and next-tier drops. Includes the map configuration and tier-specific monster rewards.

1. Prepare data2. Configure3. Use the map4. Adapt it

What to create or confirm

File / systemRequired work
ItemsDefine custom item codes nm1, nm2 and nm3, including their ordinary item data and display strings. Supply the initial nm1 through your mod’s existing acquisition path.
CubeMainThree exact Red Portal recipes: nm1, nm2 and nm3.
TreasureClassExMapping_Tier1 rewards nm2; Mapping_Tier2 rewards nm3. Keep these roots out of ordinary monster TC trees. These examples replace normal skeleton1 rewards rather than adding to them.
Levels / statsSix disjoint groups shown below; resistance IDs 39/41/43/45, physical resistance 36, monster movement 67, MF 80 and XP 85.

See how to find data IDs, CubeMain row syntax and HUD appearance settings.

Use the item, Level, stat and skill IDs from your effective mod data. The complete TOML below does not create TXT rows. If you change an input combination, update both CubeMain and its route.

The decisions in this configuration

  1. Give each tier its own destinations

    tier1 owns [2] and [3]; tier2 owns [8,9] and [10]; tier3 owns [21,22,23] and [24,25]. The non-overlapping groups can stay active together; each remains in later weighted selections.

  2. Build the fixed difficulty baseline

    Ranks 1–3 use monster elemental-resistance bonuses +0/+5/+10 and density 150/200/250%. Each map also selects one paired challenge/reward trait.

  3. Connect rewards to the next entry recipe

    The tier1 and tier2 groups use skeleton1 monster pools. The companion monstats.txt replaces their normal-monster TCs with Mapping_Tier1 and Mapping_Tier2 in all three difficulties. These TCs can supply nm2 and nm3 for the next recipe. Tier3 has no TC replacement rule.

  4. Author the TC contents in TXT

    In your mod’s TreasureClassEx, set Mapping_Tier1 to drop nm2 and Mapping_Tier2 to drop nm3, with the chances you want. The plugin’s monstats.txt selects these TCs for each tier.

Install the matching monster TC table

Download monstats.txt and save it inside d2rl-native-mapping.mpq/data/global/excel/d2rloader/native-mapping/ beside the DLL. Keep the MPQ as a folder. If you already have rules, merge these rows under one header and avoid duplicate tier/target pairs. See the setup instructions.

Companion monstats.txt · required alongside this TOML

This example deliberately gives normal skeleton1 drops only the chance-based next-tier item. To retain other loot, include it in the replacement TC. Special or quest drop rules can select other fields. Restart after changing either file, and use matching rules on Host and Join.

# Requires custom nm1/nm2/nm3 items and exact Red Portal CubeMain recipes.
# Define Mapping_Tier1 and Mapping_Tier2 in TreasureClassEx before enabling.
# Tier-specific rewards require a separate monstats.txt configuration.
# Edit this file inside the d2rl-native-mapping.mpq folder beside the plugin DLL:
# data/global/excel/d2rloader/native-mapping/monstats.txt
# For skeleton1, set TreasureClass, TreasureClass(N) and TreasureClass(H) to
# Mapping_Tier1 in tier1 and Mapping_Tier2 in tier2.
# This changes normal-monster rewards in Normal, Nightmare and Hell.
# Other drop categories keep their original TC fields.
# Levels and stats below are illustrative; use effective mod data.
config_version = 1

[traits.hunters]

  { stat_id = 67, target = "monster", value = 20 },
  { stat_id = 80, target = "player", value = 50 }
]

  { stat_id = 36, target = "monster", value = 10 },

What the player should experience

Action / resultExpected behavior
Open with nm1One tier1 group becomes active with skeleton1 pools. Its normal skeleton1 drops use Mapping_Tier1. Champions, uniques and other unconfigured categories keep their original TC fields.
Find nm2 and use its recipeA tier2 group can open in the same game without retiring tier1 because their Levels do not overlap. Overlapping designs can also be crafted after the full replacement area is clear.
Finish tier3Normal and trait-based gameplay continue. No automatic completion reward or tier3 TC replacement is configured.
Repeat a tierBoth groups remain in every roll. A selected active group is replaced after everyone leaves and its rooms are ready; there is no two-crafts-per-game limit. Re-entry without crafting preserves the current run.

Use the recipe with the required ingredients, enter its portal, and open the automap. Before repeating a craft, follow the repeat-craft procedure to collect items and clear the area. Check the tier, density and effect text against the result above.

A next-tier item is a chance-based TC reward here, not a map-clear reward. Finding the next entry item depends on the TC you configured.

Change the behavior intentionally

Add tier3 crafting rewards
Define a dedicated reward TC and add a tier3 row for your chosen target in the companion TC table. Choose the rewards you want for the final tier.
Use a shared destination pool
Follow the shared-pool example: a new selection can replace an earlier tier’s entire overlapping group after the area is clear.
Add a premium tier2 recipe
Point a distinct exact recipe to tier2 and attach a modifier. Keep the original tier2 route for the ordinary item.

When merging this design into your existing TOML, copy its referenced traits and modifiers as well as the route and tier. Keep only one root configuration and HUD table, rename colliding identifiers consistently, and check Level overlap across every tier to understand which entire groups will be replaced.
